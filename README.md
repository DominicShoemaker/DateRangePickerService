# API Documentation & Architecture: CasaDePedra DateRangePickerService

## High-Level Summary
The `DateRangePickerService` is a C# .NET Azure Functions application for Casa de Pedra reservation availability, pending holds, Stripe checkout, cancellation, and payment webhooks. It persists reservations through the Google Calendar API and supplementary external iCal feeds. Authoritative prices come from the separately deployed JavaScript pricing API configured by `PricingApiBaseUrl`.

The architecture fundamentally bypasses traditional relational database requirements by treating Google Calendar as the central source of truth for concurrency and availability. Stripe API integration handles payment processing, interacting via asynchronous webhooks to transition bookings from 'Pending' to 'Reserved' automatically.

---

## Core API Endpoints

### 1. Reservation Management (`Reservation.cs`)

#### `GET /api/Reservation/{reservationid?}/{from?}/{to?}`
Fetches reservations from the main Google Calendar and supplementary `.ics` URLs.
- **Without Parameters**: The function returns a list of all "Reserved" bookings across configured calendars.
- **With Parameters (`reservationid`, `from`, `to`)**: Fetches a specific event. If the requested event has a "Pending" status, the function proactively verifies that there are no overlapping "Reserved" bookings within its date range. If an overlapping "Reserved" event is detected, the "Pending" reservation is immediately removed from the calendar.
- **Why**: By aggressively aggregating multiple `.ics` feeds alongside native Google Calendar events, the system prevents double bookings across platforms (like Airbnb). The "Pending" overlap check allows the application to cleanly garbage-collect invalid pending blocks that conflicted with a confirmed reserved booking.
- **Returns**: A JSON array of dictionaries, exposing blockouts via `{ "From": DateTime, "To": DateTime }`. If checking a specific `reservationid` without overlap, returns detailed metadata (`FullName`, `Email`, `Phone`, `Status`).
- **Potential Exceptions**: Returns HTTP 500 on `FileNotFoundException` or `InvalidOperationException` if `calendars.json` or GCP credentials are unconfigured.

#### `POST /api/Reservation`
Attempts to create a "Pending" reservation block on the Google Calendar.
- **Why**: Establishing an unconfirmed "Pending" event acts as a soft-lock on the dates while the user is routed to complete their Stripe checkout, guaranteeing their availability temporarily.
- **Body Arguments**:
  - `From` | `To` (DateTime string): The bounds of the reservation checkout.
  - `Email` | `fullName` | `Phone` | `Source` (string): Contact info injected securely into Calendar `ExtendedProperties`.
- **Returns**: `201 Created` with payload `{ ReservationID: <GoogleEventId> }` or `400 BadRequest` if the requested date range overlaps with existing reservations.
- **Potential Exceptions**: `JsonException` for malformed bodies.

#### `DELETE /api/Reservation/{reservationid}/{from}/{to}`
Removes an unfinalized or cancelled reservation from the Google calendar.
- **Why**: Clears database constraints so a stale, unpaid "Pending" request doesn't block legitimately paying customers. Ensures paid/external reservations are immutable through this endpoint.
- **Parameters**: `reservationid` (string, required). `from` / `to` (string, required).
- **Returns**: `200 OK` or `400 BadRequest` if trying to maliciously delete a "Paid" reservation or one generated by an external source. Catches Google API Not Found errors mapping them securely to a standard HTTP 404.

### 2. Payment Gateway (`Reservation.cs`)

#### `POST /api/Payment`
Initializes a secure Stripe Checkout session.
- **Why**: Re-evaluates pricing logic purely on the backend to enforce the correct total avoiding typical exploit vectors where a client might tamper with front-end price requests.
- **Body Arguments**:
  - `reservationID` (string): Internal ID mapping to the calendar element. The Function reads the reservation dates from Google Calendar and requests the authoritative amount from `PricingApiBaseUrl`; it does not trust a browser-supplied amount.
- **Returns**: `200 OK` exposing `{ url: <StripeCheckoutUrl> }` to redirect the user.
- **Potential Exceptions**: Returns `400 BadRequest` if the proposed `amount` violates internal price rule validation calculations, or `404 NotFound` if the reservation mapping does not exist.

#### `POST /api/Webhook`
Standard asynchronous Stripe Webhook Listener.
- **Why**: Ensures safe finalization of states. Connects the dots when a `checkout.session.completed` event is pinged: updates Google events from "Pending" to "Paid", fires off a booking confirmation via Azure Communication Services, or terminates stale events completely on `checkout.session.expired` to cleanly free up availability.
- **Returns**: Immediately drops a `200 OK` back to Stripe to acknowledge payload delivery, preventing duplicate webhooks.

## Technical Design Decisions

### Single Source Of Truth (SSOT)
By utilizing Google Calendar's metadata features (`ExtendedProperties.Private__`) driven via OAuth2 (`GCP_SERVICE_ACCOUNT_KEY`), the application offloads scheduling complexity, concurrency logic, and schema management entirely to Google. Booking data remains abstracted out of the public description. 

### Authoritative pricing boundary
`POST /api/Payment` derives the reservation dates from the server-owned Google Calendar event and calls the JavaScript pricing API over HTTPS. A pricing failure returns `503` and prevents Stripe Checkout creation; browser totals are never accepted as authoritative.
